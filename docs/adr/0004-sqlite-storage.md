# ADR-0004: 記録の保存先にSQLiteを使う

## ステータス

Proposed

## 背景

[ADR-0002](0002-hybrid-recording-granularity.md)により、保存されるのは1秒ごとの集約値と、
異常区間の20msフレーム値の2種類になる。量の見積もりは、常時層が1時間3600行、1日8時間として
約29,000行/日。詳細層は1件あたり数百フレーム程度で、発生頻度に依存する。

分析UIは「この時間帯どうだったか」という時間範囲の問い合わせを行う。
また要望書はクラウドにデータを送らないことを求めており、保存先はローカルに閉じる。

## 決定

SQLiteを使う。データベースファイルはユーザーのアプリケーションサポートディレクトリ配下に置く。

## 影響

- 時間範囲での問い合わせが素直に書けるため、分析UIの実装が単純になる。
- 単一ファイルでサーバープロセスが不要。クラウドに送らないという要件と自然に整合する。
- 書き込みがアトミックであり、クラッシュや強制終了で記録全体が壊れるリスクが小さい。
- 上記の行数規模であればSQLiteの性能は問題にならない。
- **突合用の持ち出しには変換処理が必要になる。** SQLiteのファイルをそのまま渡すのではなく、
  必要な時間範囲を抽出して交換用の形式に変換する処理を書くことになる
  ([ADR-0006](0006-file-exchange-before-p2p.md))。
