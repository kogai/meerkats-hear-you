# ADR-0006: 突合は初期版ではファイル交換で行い、P2Pは後回しにする

## ステータス

Proposed

## 背景

要望書はデータのやり取りについてこう書いている。

> データのやり取りがどうしても必要なら、システムを迂回して人間に送ってもらうか、
> エージェント同士のP2Pにする。ただしP2Pでも暗黙に送ることはNG。

つまりファイル経由の受け渡しは、P2Pと並ぶ選択肢として明示的に許容されている。

P2Pを実装する場合、macOS同士であればNetwork.framework + Bonjourで同一LAN内の探索と接続がそのまま
書ける。ただし探索・接続・認証・転送の一式が必要になり、さらに「暗黙に送らない」ことを担保する
同意フローも別途要る。

## 決定

初期版では、記録の指定範囲をファイルに書き出し、利用者が任意の手段で相手に渡し、相手のアプリが
それを取り込む方式とする。P2Pは後続の最適化として扱う。

## 影響

- 初期版にネットワーク関連のコードが一切入らない。実装量と、考慮すべき障害モードが大きく減る。
- **「暗黙に送ることはNG」という要件が構造的に満たされる。** 書き出しも受け渡しも利用者の明示的な
  操作でしか起きず、アプリが自発的に通信する経路そのものが存在しない。
- **突合のたびに手作業が発生する。** 頻繁に突合するようになれば負担になり、その時点がP2Pを導入する
  判断点になる。
- 交換用のファイル形式を定義する必要がある(内部保存のSQLite形式とは別に、相手のアプリが安定して
  取り込める形式として決める)。
