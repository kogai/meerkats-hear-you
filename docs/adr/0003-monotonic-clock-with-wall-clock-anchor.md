# ADR-0003: 記録は単調時計と実時刻アンカーの両方で時刻を持つ

## ステータス

Proposed

## 背景

要望書は「発話と相手側の聞こえ方を突合出来るようにもしたほうがいいだろう」としている。突合は、
2台の別のMacがそれぞれ記録した時系列を並べる作業であり、時刻の共通基盤がなければ成立しない。

一方、単一マシン内の記録にも要件がある。実時刻(wall clock)はNTP同期の補正やスリープ復帰で
不連続に動きうるため、これだけを使うと記録の順序や区間長が壊れる場合がある。

突合の実装自体は後回しと決めている([ADR-0006](0006-file-exchange-before-p2p.md))。しかし時刻の
持ち方は記録済みデータの構造そのものであり、**後から遡って入れ直すことができない**。したがって
突合を実装するより前に決めておく必要がある。

## 決定

- セッション内の各レコードは、**セッション開始からの単調時刻**(monotonic clock)を持つ。
- **セッション自体が実時刻のアンカー**を持つ(セッション開始時点の実時刻と、それに対応する単調時刻)。
- 実時刻が必要な場面では、アンカーから換算する。

## 影響

- スリープやNTP補正があっても、セッション内の区間長と順序は壊れない。
- 2台の記録の突合は、それぞれの実時刻アンカー経由で行える。macOSは既定でNTP同期しており、
  発話区間(数百ms単位)の対応付けには十分な精度が見込める。
- **突合の精度はNTP同期の精度に依存する。** ずれが問題になる場合は、突合時に相互相関などで
  オフセットを推定する追加の仕組みが必要になる。その場合も本決定のデータ構造はそのまま前提として使える。
- レコードごとに時刻を2種類持つわけではない(アンカーはセッション単位)ため、保存量への影響はほぼない。
