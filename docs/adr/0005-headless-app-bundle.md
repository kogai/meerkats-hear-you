# ADR-0005: エージェントはUIを持たない .app バンドルとして常駐させる

## ステータス

Accepted (2026-09-11)

## 背景

当初このADRは「エージェント・常時表示UI・分析UIを単一プロセスにまとめるか、別プロセスに分けるか」
という問いを立てていた。しかし**UIは事実上不要という判断になったため、この問い自体が成立しなくなった。**
分けるべきUIが存在しないなら、プロセス構成の比較にならない。

残る本当の問いは1つだけである。**UIを持たない常駐プロセスに、どうやってマイクの権限を持たせるか。**

### macOSの権限(TCC)はコード署名に紐づく

マイクへのアクセスは、要求するプロセスのコード署名上の同一性に対して付与される。加えて
`NSMicrophoneUsageDescription` が必要になる。ここから2つの制約が出る。

- **素の実行ファイルは自分の名前で権限を持てない。** ターミナルから起動した場合、権限はターミナルに
  対して付与され、プロセスはそれを継承する形になる。実機検証([mac-mic-verification-result.md](../experiments/mac-mic-verification-result.md))
  でも実際にそうなっており、スクリプトの案内はターミナルへのマイクアクセス許可を促すものになっていた。
  常駐エージェントがターミナルの権限に相乗りするのは、起動経路の面でも利用者から見た分かりやすさの
  面でも成立しない。
- **署名が変わると権限が失われうる。** ad-hoc署名はビルドのたびに同一性が変わるため、リビルドごとに
  許可を求め直すことになりかねない。

つまりUIの有無とは無関係に、**エージェントは自分自身の安定した署名上の同一性を持つ必要がある。**
`.app` バンドルはそれを最も素直に満たす形式であり、`Info.plist` も自然に収まる。

## 決定

- エージェントを `.app` バンドルとして作る。ただし **UIは持たない。** `LSUIElement` を指定し、
  Dockアイコン・ウインドウ・メニューバー項目のいずれも持たないバックグラウンドプロセスとする。
- ログイン時の常駐には `SMAppService`(macOS 13以降)もしくは LaunchAgent を使う。
- 記録の閲覧は当面、[ADR-0004](0004-sqlite-storage.md)のSQLiteファイルを直接参照する
  (`sqlite3` コマンド等)。専用の分析UIは作らない。

## 影響

- **バンドルはUIのためではなく、権限のために必要である。** これは当初のADRと結論が同じでも理由が違う。
  UIを削っても `.app` を作る必要は消えない。
- 要望書が挙げていた2つの用途のうち、「指摘されずとも聞き取りづらくなっていたら**気づける**」ほうは
  現状では満たされない。記録は残るが、その場で知る手段がないためである。最小の手段は異常検知時の
  通知だが、現時点では作らない。
- 分析は当面SQLiteへの直接問い合わせになる。[ADR-0004](0004-sqlite-storage.md)で常時層をBLOBではなく
  行として持つと決めているため、`sqlite3` で素のSQLを書けば用は足りる。
- **開発中の署名の扱いが課題として残る。** ad-hoc署名のままだとリビルドのたびにTCCの許可を求め直す
  可能性がある。安定した自己署名証明書を用意して同一性を固定するか、開発中の再許可を受け入れるかの
  選択になる。
- **未検証の前提がある。** Xcodeを使わずに `.app` バンドルを組み立て、署名し、TCCの許可を得て維持する、
  という一連が実際に通るかは確認していない([ADR-0001](0001-swift-macos-only-agent.md)で挙げた
  未検証部分と同じもの)。最小のスパイク(SPMでビルド → バンドル組み立て → 署名 → 常駐起動 →
  マイク権限取得 → 数秒キャプチャ → リビルドして権限が維持されるか確認)を一本通せば決着する。
  ここが崩れる場合、影響はADR-0001の「Xcodeを使わない」という判断にまで及ぶ。

## 検討した代替案

### 素のCLIバイナリ + LaunchAgent

`Info.plist` をバイナリの `__TEXT,__info_plist` セクションに埋め込めば、バンドルなしでも理屈の上では
成立する。ただし署名とTCCの扱いが煩雑になり、得られるものは「バンドルを作らなくて済む」ことだけである。
バンドルの組み立て自体はビルドスクリプトの数行にすぎないため、割に合わない。採用しない。

### メニューバー常駐(当初の案)

UIが不要である以上、常駐状態を表示するためだけにメニューバー項目を持つ理由がない。将来「気づける」
ほうの用途に取りかかる時点で、通知とあわせて再検討すればよい。
