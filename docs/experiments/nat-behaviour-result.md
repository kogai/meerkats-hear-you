# 検証レポート: 手元の回線のNATの振る舞い

実施: 2026-09-24(Mac実機・実回線) / スパイク: [`experiments/nat-behaviour`](../../experiments/nat-behaviour/)

**このリポジトリは公開なので、生の出力とグローバルアドレスは載せない。**
判定はいずれもポートの一致・不一致で決まるので、アドレスが無くても読める
(スパイク側も既定でアドレスを伏せるようにした)。

## 1. 目的

[ADR-0009](../adr/0009-record-exchange-transport.md) が「未検証の前提」に **NAT越えの実挙動**を
残していた。作業環境にもCIにもNATの内側の実回線が無く、実機でしか埋まらない。

決め手は1つ。[RFC 4787](https://www.rfc-editor.org/rfc/rfc4787.html) の用語で、宛先が変わっても
外側ポートが変わらないもの (EIM) と、宛先ごとに変わるもの (EDM) があり、**EDM では穴あけが
原理的に成立しない。** ADR-0009 はそれを承知で「繋がらない相手が残る」と書き、ファイル書き出しを
落とし所に残した。知りたかったのは、**その落とし所が例外なのか常態なのか**である。

## 2. 実行環境

- 依頼は「普段オンライン会議をする回線、VPN は切って」。出力から回線の種別は判別できないので、
  そこは実行者の申告に依る
- **NAT の内側から測れている。** 経路として選ばれるローカルアドレスと反射アドレスが一致した
  場合に出る警告は、出ていない
- 公開STUNを2つ(Google / Cloudflare)使い、**別々のIPに解決されている。** 同じIPだと
  「宛先を変えた」ことにならないので、これは2節の前提になる

## 3. 結果

### 3.1 STUN は通る

1本目のソケットから公開アドレスが得られた。UDP も STUN のポートも塞がれていない。

### 3.2 宛先が変わっても外側ポートは変わらない (EIM)

同じソケットから2つのSTUNサーバへ問い合わせ、**外側ポートは同一**だった(ともに 56760)。
アドレスも同一。

**この回線では穴あけが成立する側である。** ADR-0009 の本線をそのまま実装に移せる。

### 3.3 内側のポートがそのまま外へ出る

| | 内側 | 外側 |
|---|---|---|
| 1本目 | 56760 | 56760 |
| 2本目 | 62663 | 62663 |

**付け替えていない。** ADR-0009 が EDM 相手の救済として挙げた誕生日のパラドックス(両側が
複数ポートを試す)は、**この回線側については探索の対象にならない。** 自分の外側ポートは
自分で分かるためである。相手が EDM の場合に探索が要るのは変わらない。

### 3.4 マッピングは 180 秒の沈黙後も生きている

待つ長さごとに別のソケットを使い、その間そのソケットからは1つもパケットを出していない。

| 沈黙 | 結果 |
|---|---|
| 30.0 秒 | 生きている(同じ外側ポート) |
| 90.0 秒 | 生きている(同じ外側ポート) |
| 180.0 秒 | 生きている(同じ外側ポート) |

**RFC 4787 REQ-5(2分未満で切ってはならない)を満たしている。** ADR-0009 が併記していた
「30秒程度で切る実装」には当たらない。

## 4. ADR-0009 への影響

- **本線(ランデブー + 穴あけ)は、この回線については成立する。** EDM だった場合に迫られた
  「ADR-0009 の方向そのものの見直し」は起きない
- **ADR-0014 との衝突は起きない。** ADR-0009 は 30秒側だった場合に「相手ごとに keepalive が
  常時走る」ことを懸念していたが、180秒の沈黙で切れていない。keepalive の間隔は
  **測れた 180 秒より内側**に取れば足りる
- **誕生日のパラドックスの位置づけは変わらない。** 初期版には要らない、後から足せる最適化のまま

## 5. 測っていないこと

- **相手側の回線。** 穴あけの成否は両側の組み合わせで決まる。ここで分かったのは片側だけで、
  **繋がらない相手が残るという ADR-0009 の想定は消えない。** ファイル書き出しの落とし所も残す
- **フィルタの振る舞い**(開いた穴が誰からのパケットを通すか)。RFC 5780 の NAT Behavior
  Discovery が要るが、対応する公開STUNが少なく、確実に測るには自前のサーバが2アドレス要る。
  ランデブーを立てるときに一緒に足す
- **穴あけそのもの。** 両端が要るので1台では動かせない
- **マッピングの寿命の上限。** 180秒までしか測っていない。切れる点は分かっていない
- **測定は各1回。** 時間帯や機器の状態による揺れは見ていない
